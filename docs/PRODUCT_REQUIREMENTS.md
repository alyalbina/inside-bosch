# Product requirements · version 0.3

**Purpose:** an evidence-based journey into The Garden of Earthly Delights. A visitor can zoom into any region, inspect selected scenes, compare motifs, consult sources and preserve their own questions without registering.

## Implemented acceptance scope

- Native-resolution tiled interior viewer with OpenSeadragon; pan, zoom, bounds, navigator, home, touch gestures supplied by OSD.
- Actual exterior reproduction shown in the prologue; three interior chapters and an interpretative epilogue.
- 25 visual regions, 15 guided stops; the five original topics retained and corrected.
- Five comparative motif routes, related-detail links and searchable panel-filtered catalogue.
- Observation, historical/context note, sourced interpretation where available, open question and source links.
- Browser-local seen entries, favourites, private notes, journey position and started threads; JSON export.
- RU/EN UI and editorial records.
- Optional original Web Audio ambience, user-started, muted by default; volume control and text explanations.
- Error/retry states, text access independent of viewer, lazy viewer loading and lazy catalogue crops.

**What the counts mean:** 25 visually checked regions do not equal 25 independently curated symbolic explanations. Entries without a supported reading remain explicitly observation-only. Opening a detail records that it was viewed; it does not measure understanding. A thread records that it was started, not completed.

## User assumptions

Curious visitors, art enthusiasts and educators are hypotheses inherited from the original brief; no user interviews or retention claims have been invented. No quiz gates, correct-answer rewards, tracking analytics, accounts or backend.

## Release limits

Automated build, content/geometry/navigation-state and asset checks are available. Browser/device interaction testing and independent scholarly signoff have not been completed in this environment. This is a reviewable version 0.3, not a completed commercial release. Native touch/pinch and accessibility mechanisms require device validation.
